# Этап 1. Исследование существующих решений

Дата проверки: 2026-10-26. Каждый репозиторий клонирован и прочитан (код, README,
внутренние docs, история коммитов); выводы ниже основаны на коде, а не на
заявлениях в README.

## Как проверялась работоспособность

Живой проверки парсеров из среды исследования **не было**: сетевая политика
контейнера отклоняет соединения с `avito.ru`, `ozon.ru`, `wildberries.ru`,
`wb.ru`, `market.yandex.ru` (ответ прокси 403). Поэтому «работает сейчас» ниже —
это вывод из кода и из того, что сами авторы пишут о своих проверках, а не
собственный замер. Для проверки на домашнем сервере в проекте есть команда
`sniflot probe <source> "<запрос>"` (см. README).

## Состояние площадок (по коду и отчётам авторов)

### Wildberries — лучший кандидат для первого адаптера
- Публичный JSON-поиск без авторизации и без браузера:
  `https://search.wb.ru/exactmatch/ru/common/v{N}/search?query=…&dest=…&page=…&sort=…&resultset=catalog`.
  Номер версии меняется: marketplace-mcp на 2026-07…09 использует `v9` с тестом
  «stable v9», статья на Хабре — `v18`; статья на vc.ru пишет, что путь `/catalog/`
  отдаёт 404 и что шард бывает в пути. **Вывод:** URL должен быть настраиваемым,
  адаптер пробует несколько версий и запоминает рабочую.
- Карточка: `https://card.wb.ru/cards/v4/detail?nm=<id>&dest=…`.
- Цены в копейках: `sizes[].price.product` (текущая), `sizes[].price.basic` (до скидки),
  в старых ответах — `salePriceU`/`priceU`. Цена в ответе не учитывает WB Кошелёк.
- `dest` — регион/склад, от него зависят цена и наличие (`-1257786` — Москва).
- Ограничение частоты: мягкий лимит порядка 50 запросов/мин, 429 — не бан
  ([vc.ru](https://vc.ru/marketing/3103948-poisk-wildberries-api-shardirovanie-obhod-banov)).
  marketplace-mcp отмечает, что длинный Chrome UA получает 429 чаще, чем короткий.
- Риск: эндпоинт недокументирован, может измениться без предупреждения.

### Avito — доступ ограничен, только как экспериментальный источник
- Данные страницы лежат в `<script type="mime/invalid" data-mfe-state="true">`
  (HTML-экранированный JSON) → `loaderData.data.catalog.items`, пагинация — `catalog.pager.next`.
  Более старый формат — `window.__initialData__` (domovoyproj). Это два разных
  формата в проектах с разницей в месяц — разметка меняется часто.
- Защита (Qrator/Curator): блок IP «Доступ ограничен: проблема с IP», капча,
  TLS-фингерпринт. Все рабочие решения либо покупают cookies и ротируют
  мобильные прокси (avito-mcp-plugin, Duff89), либо просят человека пройти капчу
  в видимом браузере (domovoyproj). Ни один автор не подтвердил стабильную работу
  с обычного домашнего IP; avito-mcp-plugin прямо пишет о 403/429 после 2–3 запросов.
- **Вывод:** адаптер Avito делаем вежливым (редкие запросы, без подделки TLS,
  без покупки cookies и прокси), при первой блокировке источник уходит на паузу
  с нарастанием, а пользователь видит статус. Это значит, что на части IP Avito
  работать не будет — так и документируем.

### Ozon и Яндекс Маркет — нужен браузер, вне MVP
- Без JavaScript Ozon возвращает антибот-заглушку (marketplace-mcp: «Disabling
  JavaScript is not a useful fallback»), headless детектится, автор держит headful.
- Я.Маркет — та же схема: отрисованная страница + снимок доступности.
- **Вывод:** для них нужен Playwright с видимым браузером; это тяжёлая зависимость,
  поэтому отложено до v0.3 и только для отслеживания карточек по URL, не для поиска.

## Что переиспользуем

| Компонент | Решение | Почему |
|---|---|---|
| Знание эндпоинтов и полей WB | адаптируем по описанию из marketplace-mcp (MIT), код пишем свой | своя модель данных, но поля и единицы те же |
| Формат SSR-JSON Avito и признаки блок-страницы | адаптируем по описанию из avito-mcp-plugin (MIT) | маркеры `firewall-container` и т. п. — факт о странице |
| Состояния проверки (ok / empty / blocked / error) и паузы после блокировки | идея из domovoyproj и marketplace-mcp | blocked никогда не трактуется как «объявления пропали» |
| Сохранение последней доверенной цены при сомнительном извлечении | идея из centsible | защита от ложных уведомлений |
| Уведомления в 90+ сервисов | [Apprise](https://github.com/caronc/apprise) (BSD-2) — опциональный канал в v0.2 | не пишем свой зоопарк уведомлений |
| Отслеживание произвольных магазинов | JSON-LD `Product/Offer` (как в changedetection.io/centsible), v0.2 | стандарт schema.org, без селекторов под сайт |
| HTTP | `httpx` (уже зависимость FastAPI-экосистемы) | `curl_cffi` нужен только для подделки TLS — не используем |
| Планировщик | свой цикл на asyncio со сроками в SQLite (~60 строк) | APScheduler здесь избыточен: задачи и так хранятся в БД, переживают рестарт |

Сами приложения (PriceBuddy, changedetection.io) не подходят как основа: оба
ориентированы на отдельные URL, не на поиск по площадкам, и тянут
MySQL/Selenium/Playwright. При желании их можно держать рядом для магазинов,
которые наш проект не поддерживает.

## Чего не делаем

- Не подделываем TLS-отпечаток, не покупаем cookies, не ротируем прокси для
  обхода блокировок, не решаем капчу, не используем stealth-плагины.
- Не собираем телефоны и персональные данные продавцов.
- Не выдаём проиндексированные поисковиком ссылки за актуальные цены.
